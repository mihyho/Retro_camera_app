# Retro_camera_app

필름 카메라 색감(3D LUT)을 **카메라 프리뷰와 촬영본에 똑같이** 입히는 안드로이드 카메라 앱입니다.
실제 필름처럼 한 롤(24/36장)을 다 찍을 때까지 필름을 바꿀 수 없고, 사진은 롤이 끝나야 "현상"되어 보입니다.

## 핵심 기능

- **필름 모드**
  - 필름(프리셋) 1개와 24장 또는 36장을 장전하면, 다 찍을 때까지 다른 필름으로 바꿀 수 없습니다.
  - 남은 장수는 프레임 카운터 다이얼에 표시됩니다.
  - 촬영 직후에도 사진은 보이지 않습니다(앱 전용 폴더에만 저장). 필름 모드 촬영본에는 필름 그레인이 들어갑니다.
  - 마지막 장을 찍으면 "현상"되어 사진이 갤러리로 내보내지고, 잠금이 풀립니다.
- **필름 버리기:** 설정 화면에서(진행 중인 롤이 있을 때만 보임) 중간에 포기하고 새로 시작할 수 있습니다. 확인 창을 거치고, 찍은 사진은 모두 삭제되며 되돌릴 수 없습니다.
  롤 상태를 먼저 지우고 파일을 나중에 지워서, 삭제 도중 앱이 죽어도 롤이 되살아나지 않고 남은 파일은 다음 실행 때 정리됩니다. 단일 촬영 사진, 이미 현상된 롤, 설정은 그대로입니다.
- **카메라 확대:** 뷰파인더에서 두 손가락으로 벌리거나 오므려 확대/축소하고, 두 번 탭하면 1배와 2배를 오갑니다. 확대 중에는 배율이 표시됩니다(서랍/패널이 열려 있으면 비활성).
- **단일 촬영 모드**
  - 잠금 없이 필름을 자유롭게 바꾸고, 찍은 사진은 바로 갤러리에 저장되며 바로 볼 수 있습니다.
  - 진행 중인 필름 롤은 멈춘 채 그대로 유지됩니다.
- **영구 저장**: 앱을 강제 종료하거나 재부팅해도 남은 장수가 유지됩니다. 앱 데이터를 지우거나 재설치하면 롤은 초기화됩니다(의도한 정책).
- **디자인**: 구형 디지털카메라 몸체(검은 플라스틱, MENU/십자키/SET/DISP, 촬영·재생 전환, 아래줄 가운데 셔터)와 가운데 LCD. 어느 버튼을 눌러도 몸체는 바뀌지 않고, 설정·재생·현상·필름 메뉴는 LCD 안에서만 열립니다.
  - **십자키:** 메뉴가 열려 있으면 ▲▼ 줄 이동, ◀▶ 값 변경, SET 선택. 메뉴가 없을 때는 ▲▼ 확대, ◀▶ 필름 바꾸기(롤 중에는 잠금), SET 필름 메뉴. MENU는 설정, DISP는 격자 켜기/끄기.
  - **재생:** 누르면 마지막에 찍은 사진 한 장을 LCD 가득 보여 줍니다. ◀▶(또는 옆으로 밀기)로 넘기고, ▼/SET으로 3열 목록, 목록에서 SET으로 다시 한 장 보기. 진행 중인 롤의 사진은 롤이 끝날 때까지 보이지 않습니다.
  - **볼륨 버튼 촬영:** 설정에서 켜고 끌 수 있고 기본은 켬입니다. 켜져 있으면 볼륨 버튼이 셔터이고 시스템 볼륨 조절은 막습니다.

## 빌드와 실행

요구 사항: Android Studio(번들 JBR 사용), Android SDK 36, minSdk 29(Android 10) 이상 기기.

```bash
cd FilmCamera
# 시스템 JDK가 너무 새로우면(예: 26) AGP가 실패하므로 Android Studio의 JBR을 쓰세요
export JAVA_HOME="C:/Program Files/Android/Android Studio/jbr"
./gradlew :app:assembleDebug        # 디버그 APK
./gradlew :app:testDebugUnitTest    # 단위 테스트
```

Android Studio에서 `FilmCamera` 폴더를 열면 `local.properties`(SDK 경로)가 자동으로 만들어집니다. 이 파일은 저장소에 포함되지 않습니다.

**디버그 빌드에서만** 설정 화면에 "프로토타입 테스트" 버튼이 보입니다.

- 남은 장 모두 찍기: 남은 장수를 가짜 사진으로 채워 롤 종료(현상) 흐름을 바로 시험합니다.
- 앱 데이터 지우기: 롤과 사진 목록을 초기화합니다.

## 필름(LUT) 만들기

프리셋은 같은 장면의 보정 전/후 사진 한 쌍(여러 장면을 합칠 수도 있음)에서 3D LUT를 뽑아 만듭니다. 앱 사용자가 사진을 입력하는 기능은 없고, 개발 단계의 오프라인 작업입니다.

```bash
pip install numpy pillow scipy
```

**필름 3종을 한 번에 만들기** — 사진 쌍을 필름별 폴더에 `<이름>_before.<확장자>` / `<이름>_after.<확장자>` 로 넣습니다.

```
local/samples/
  gold/       seoul_before.webp   seoul_after.webp
              street_before.jpg   street_after.jpg      ← 쌍은 필름당 2~4개 권장
  tungsten/   ...
  forest/     ...
```

```bash
python tools/build_luts.py           # 사진 쌍이 있는 필름만 만든다(없는 필름은 건너뛰고 기존 LUT 유지)
python tools/build_luts.py gold      # 특정 필름만
```

결과는 `FilmCamera/app/src/main/assets/luts/<필름>.cube`에 저장되고, 확인용 비교 이미지는 `local/luts/<필름>_check.jpg`에 생깁니다.

**한 파일만 만들기**

```bash
python tools/extract_lut.py my_film.cube before1.jpg after1.jpg [before2.jpg after2.jpg ...]
```

- 각 before/after 쌍은 같은 장면, 같은 구도(크롭하지 않은), 같은 해상도여야 합니다.
- 출력되는 "검증 오차"는 학습에서 뺀 영역(각 쌍의 아래 30%)의 오차이고, 학습 영역 오차보다 높게 나오는 것이 정상입니다.
- 사진 한 쌍으로는 그 장면에 없는 색(피부톤, 빨강, 보라, 실내 조명)을 추정할 수밖에 없으므로, 필름마다 서로 다른 장면 2~4쌍을 합치는 것을 권장합니다.

**LUT 품질 장치** (`tools/extract_lut.py`)
- **보정 규칙 학습(전역 모델):** 사진에 나온 색만 외우면 처음 보는 색에서 엉뚱해지므로, 먼저 "보정이 색을 어떻게 바꾸는가"를 규칙으로 배웁니다.
  색을 Oklab(밝기 L, 색 a·b)으로 바꾼 뒤 **밝기별로** 밝기 곡선(그림자 들뜸, 대비), 채도와 색상 이동, 틴트(그림자/하이라이트에 입히는 색)를 학습합니다. 규칙은 특정 색이 아니라 밝기에 의존해서 모든 색에 적용됩니다.
  - **색온도/틴트:** 원래 회색이던 픽셀이 어느 색으로 변했는지로 전역 색온도 이동을 따로 잽니다. 밝기 구간마다 방향이 다르면(그림자는 차갑게, 밝은 곳은 따뜻하게 같은 스플릿 톤) 전역 이동으로 보지 않습니다.
  - 학습 데이터가 없는 밝기 구간은 원본 쪽으로 서서히 되돌립니다.
- **파라미터 룩(사진 쌍을 쓰지 않는 필름):** `tools/build_luts.py`의 `LOOKS`에 적은 필름은 사진에서 학습하지 않고 값으로 룩을 정합니다. 보정 사진을 학습하면 그 사진의 바램/낮은 대비까지 따라가서 색이 죽기 때문입니다.
  **텅스텐:** 색온도 3300K(낮 햇빛 장면이 차갑게), 빨강/초록/파랑 채도 +40%, 하이라이트 밝기 상승, 대비 0.80배(중간 톤 기울기를 완만하게).
  색온도로 1.0을 넘은 색은 자르지 않고, 마지막에 채도만 줄여 표현 범위 안에 넣습니다.
  파랑은 3300K의 파란 이동 때문에 이미 표현 범위(sRGB) 끝에 있어서 채도가 거의 오르지 않고, 파란 기가 도는 회색과 중립색의 채도가 오르며 화면 전체가 더 푸르러집니다.
- **색상 범위 보정(`POST`):** 만든 LUT 위에, 정한 색상(Oklab 색상각 주변)에만 채도와 색조 이동을 얹습니다. 다른 색은 그대로입니다.
  **포레스트:** 초록에만 채도를 올리고 색조를 청록 쪽으로 약간(+8°) 돌립니다. 실제 숲 사진에서 초록 채도가 약 +14%, 색상각이 약 +5° 움직였습니다.
  아주 짙은 초록은 이미 sRGB 표현 범위 끝에 가까워서 채도를 더 올릴 수 없고(청록 쪽으로 돌리면 오히려 약간 줄어듦), 밝은 초록은 크게 오릅니다.
- **장면 고유 보정(잔차):** 규칙으로 설명되지 않는 미세한 보정은 색 데이터가 있는 곳에서만 LUT에 더합니다(`GATE_SIGMA`, `GATE_REF`).
- **색 공간 변환:** Display P3 같은 ICC 프로파일이 든 사진(아이폰 등)은 sRGB로 변환해서 학습합니다(앱의 카메라 프레임이 sRGB 기준).
- **기울기 상한:** LUT가 입력의 작은 차이를 크게 벌리는 구간(노이즈 증폭, 밴딩의 원인)을 펴 줍니다(`MAX_GAIN = 2.0`).
- **니콘 레시피(.NP3) 5종:** Ektar100, KGold200, KPortra800, Provia100F, WarmAutumn은 `python tools/np3_to_lut.py <NP3 폴더>`로 근사 변환합니다. NP3는 색 표가 아니라 슬라이더 값(톤 커브, 컬러 블렌더, 컬러 그레이딩)이라 니콘 내부 처리와 똑같지는 않습니다. 색조/채도/밝기 배율(`HUE_MAX` 등)은 가정값이니 폰에서 보고 조정하세요. 레시피 제작자의 이용 조건은 직접 확인하세요.
- **교차 시험:** `python tools/cross_check.py` — 3종 LUT를 학습에 쓰지 않은 장면에 적용해 `local/luts/cross_check.jpg`로 저장합니다. LUT를 새로 만들 때마다 눈으로 확인하세요.

## 필름 룩: 명료도와 그레인

모든 필름에 공통으로, 필름마다 `Film`(`data/Model.kt`)의 값으로 정합니다. 촬영본과 프리뷰 셰이더에 같은 수식을 씁니다.

- **명료도 낮춤 = 가우시안 흐림을 섞은 사진:** `결과 = 원본 + (가우시안 흐림 - 원본) × 강도 × 경계 보호`. 기본값 `clarity = -0.40`(질감/면에 흐림 40% 혼합).
  **피사체의 뚜렷한 경계선은 흐려지지 않게** 원본과 흐림의 밝기 차이가 큰 곳은 흐림을 섞지 않습니다(`Clarity.EDGE_LOW/EDGE_HIGH`).
  실사진 3장 측정: 단순 가우시안 25%는 가장 강한 경계선의 기울기를 약 21% 깎았고, 이 방식은 약 6%만 깎으면서 질감은 부드럽게 만듭니다.
  흐림 세기는 이미지 폭의 0.22%라 프리뷰와 촬영본이 같은 느낌입니다.
- **그레인:** 모든 필름에 약하게(`grain = 0.020`) 넣습니다. 촬영본에만 적용되고(프리뷰에는 없음), 필름 모드와 단일 촬영 모두에 들어갑니다.

## 노이즈

- **색감을 입힐 때 노이즈가 늘지 않게:** 색감(LUT)은 흐린 이미지에 입히고, 세부/노이즈는 원본 크기를 넘지 못하게 제한합니다(프리뷰 셰이더와 촬영본 `LutApplier.applyDetailSafe` 모두).
  실제 LUT와 장면으로 잰 노이즈 배율의 최댓값이 1.27배에서 약 1.0배로 줄었고, 테스트(`NoiseSafeTest`)로 확인합니다.
  완전한 0은 아닙니다: 흐린 이미지에 섞인 저주파 잔여 노이즈는 LUT 대비만큼 커질 수 있어, 대비를 2배 올리는 극단적인 LUT에서는 약 1.06배가 남습니다.
- **필름 그레인은 별개:** 의도해서 얹는 효과이며 LUT 단계 뒤에 적용됩니다.

## 알려진 한계

- **실제 폰에서 검증하지 않았습니다.** 모든 확인은 에뮬레이터에서 했습니다. 카메라 회전(똑바로 나오는지), 프리뷰 성능, 12MP 촬영 처리 시간, 실제 색감은 폰에서 확인이 필요합니다.
- **필름 3종의 LUT는 각각 사진 한 쌍(한 장면)으로만 만들었습니다.** 골드는 서울타워(낮), 텅스텐은 한강 야경, 포레스트는 숲(낮)입니다.
  학습 장면에 없는 색은 원본에 가깝게 두도록 안전장치를 걸었지만, 처음 보는 장면에서는 색이 어색할 수 있습니다.
  특히 **텅스텐은 야경만 학습**해서, 야경의 따뜻한 가로등 불빛이 "밝은 곳은 따뜻하게"로 일반화되어 낮 장면이 올리브색/탁한 베이지로 나옵니다. 필름마다 서로 다른 장면(낮/밤, 인물, 중립색 등) 2~4쌍을 더하면 크게 좋아집니다.
- 에뮬레이터에서는 질감(가죽, 메탈)을 스크린샷으로만 확인했습니다.
- "NO FILM" 오버레이의 배경 블러는 구현하지 않았습니다(카메라 프리뷰가 `SurfaceView`라 그 뒤를 블러 처리할 수 없어, 어두운 반투명 막만 씁니다).
- 갤러리에서 사진 삭제·공유 기능은 없습니다.
- **카메라 확대는 실제 폰에서 확인하지 못했습니다.** 에뮬레이터 카메라는 확대 범위를 1.0~1.0으로만 알려 줘서 제스처(더블탭)가 도착하는 것과 배율 표시가 그려지는 것까지만 확인했습니다. 확대 중 프리뷰와 촬영본의 화각, 12MP 촬영 시 확대 적용은 폰에서 확인이 필요합니다.
